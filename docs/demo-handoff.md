# Даник → Никита и Тимур: учебный проект и сценарии

## Что уже есть

Минимальное приложение — `demo-app/app/calc.py`, намеренный баг в `average([])`.
Это Python-модуль без FastAPI, PostgreSQL, Sentry и HTTP-сервера. Не нужно ждать этих компонентов,
чтобы проверить runner и verifier. Это начальный набор из двух сценариев, не завершённая оценка модели.
Четыре правильных ответа зафиксированы в `evaluation/oracle.py` независимо от приложения.

## Подготовка (из корня Nightwatch)

1. Создать окружение: `python -m venv .venv`.
2. Windows: `.\.venv\Scripts\Activate.ps1`; Linux: `source .venv/bin/activate`.
3. Пока `pip install -e .` имеет ошибку обнаружения нескольких пакетов, установить зависимости
   напрямую: `python -m pip install openai pydantic python-dotenv pytest`.
4. Проверить: `python -m pytest -q`.
5. Создать данные: `python -m tools.prepare_demo --output .demo-workspace`.

Последняя команда создаёт новый отдельный Git-репозиторий в `.demo-workspace/repo` с двумя коммитами:
рабочим и сломанным. SHA уже подставлены в `.demo-workspace/alerts/*.json`.
`manifest.json` помечен `fixture`: история подготовлена человеком, а не моделью.
Лог деления на ноль получен настоящим запуском; сообщение о памяти явно синтетическое.
Команда откажется перезаписывать существующую папку: для повторения выберите другой новый путь.
У созданного Git-репозитория нет remote, он никуда не публикуется.

## Никите

Передавать `RepoView` и runner путь `.demo-workspace/repo`, а не корень Nightwatch и не `demo-app`.
Загружать Alert из `.demo-workspace/alerts/empty-sample.json` либо `insufficient-evidence.json`.
Общие `Alert`, `RunResult`, протоколы и pipeline не менялись.

После настройки ключа и проверки модели можно выполнить **настоящий платный вызов**:

`python -m nightwatch.cli run --repo .demo-workspace/repo --alert .demo-workspace/alerts/empty-sample.json --runner team --verifier team`

Эта команда требует объединённых модулей runner Тимура и verifier из PR #3. Она здесь описана,
но пока не проверена: реального API-вызова в этой задаче нет. По умолчанию CLI выбирает local/reference;
это режим разработки. Не запускайте произвольные ответы модели через LocalRunner на основном компьютере.
Для второго сценария заменить только имя alert на `insufficient-evidence.json`.

Модель получает исходники отдельного демо и историю по существующему ContextBuilder.
`evaluation/`, этот документ и подготовленные оценочные патчи ей не передаются.
Предыдущая рабочая версия доступна по текущему договору; это часть выбранного командой метода.

## Тимуру

В контейнере работать с корнем сгенерированного репозитория. Импорт приложения: `from app.calc import average`.
Исходный набор: `python -m pytest -q`; четыре теста проходят на сломанном коммите.
Тест воспроизведения располагается в `tests/nightwatch/` и проверяет `average([]) == 0.0`.
На broken он падает с `ZeroDivisionError`, на good проходит. Файл ошибки — `app/calc.py`, функция — `average`.
Нельзя засчитывать ошибку импорта как воспроизведение. После патча запускать полный набор,
включая добавленный тест; вернуть настоящие nodeid, код выхода, подпись ошибки и контрольную сумму.
Проверять изоляцию, таймаут, отсутствие сети и ключей отдельно на настоящем контейнерном runner.

## Что проверяем сами и где нужны коллеги

Автотесты проверяют исходный набор, настоящий баг, good/broken, подготовленное хорошее исправление,
отказ на «всегда нули», неизменность тестов и отчёт при недостаточных данных.
На Windows / Python 3.11.9 проверено 20 октября 2026: `python -m pytest -q` — 20 тестов прошли
(15 исходных и 5 новых). Проверки verifier из отдельного PR #3 в это число не входят.
Команда подготовки `.demo-workspace` также выполнена успешно.
В проверке pipeline ответы модели записаны заранее: это проверка механизма, не качества Nemotron.
Для полного результата нужны реальный API Никиты и контейнерный runner Тимура; интерфейс проверяется позже.
Даник затем повторяет оба сценария в общей сборке и сохраняет фактические результаты.

Из PR #3 повторена одна совместимая строка: сохранять diff с LF на Windows.
Это необходимо для проверок на Windows; при объединении обоих PR изменение совпадает.
