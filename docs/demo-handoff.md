# Danik to Nikita and Timur: demo project and scenarios

## Available components

`demo-app/app/calc.py` contains the intentional `average([])` bug. This is a small Python module
without FastAPI, PostgreSQL, Sentry or an HTTP server. Runner and verifier integration can start
without those services. These two scenarios do not constitute a completed model evaluation.
Four expected answers are recorded independently in `evaluation/oracle.py`.

## Setup from the Nightwatch root

1. Create an environment: `python -m venv .venv`.
2. Windows: `.\.venv\Scripts\Activate.ps1`; Linux: `source .venv/bin/activate`.
3. The existing `pip install -e .` command has a multiple-package discovery issue. To test from
   source, install dependencies directly: `python -m pip install openai pydantic python-dotenv pytest`.
4. Run checks: `python -m pytest -q`.
5. Prepare data: `python -m tools.prepare_demo --output .demo-workspace`.

The last command creates a separate Git repository at `.demo-workspace/repo` with known-good and
broken commits. Their actual SHAs are inserted into `.demo-workspace/alerts/*.json`.
`manifest.json` is labelled `fixture`: its history is prepared by a human, not generated by a model.
The division-by-zero log comes from actual execution; the memory-pressure report is explicitly synthetic.
The command refuses to overwrite an existing directory; choose another new path to repeat setup.
The generated repository has no remote and is never published by this command.

## For Nikita

Pass `.demo-workspace/repo` to `RepoView` and the runner, rather than the Nightwatch root or `demo-app`.
Load Alert from `.demo-workspace/alerts/empty-sample.json` or `insufficient-evidence.json`.
Shared `Alert`, `RunResult`, protocols and pipeline are unchanged.

After configuring the key and validating model access, a live, billable model run would use:

`python -m nightwatch.cli run --repo .demo-workspace/repo --alert .demo-workspace/alerts/empty-sample.json --runner team --verifier team`

This command requires Timur's runner and the verifier from PR #3 to be integrated. It is documented
but has not been validated with a live API call in this task. CLI defaults remain local/reference,
which is a development configuration. Do not execute arbitrary model responses with LocalRunner
on the host computer. For the second scenario, change the alert filename to `insufficient-evidence.json`.

The existing ContextBuilder provides the model with demo sources and history. Do not supply
`evaluation/`, this document or prepared evaluation patches to the runtime model. The known-good
history is available under the existing team contract and is part of the chosen method.

## For Timur

Use the generated repository root inside the container. Application import: `from app.calc import average`.
Original suite: `python -m pytest -q`; four tests pass on the broken commit.
Place the reproducer under `tests/nightwatch/` and assert `average([]) == 0.0`.
It fails on broken with `ZeroDivisionError` and passes on good. Error file: `app/calc.py`; function: `average`.
An import error must not confirm reproduction. After a patch, run the full suite including the reproducer;
return actual nodeids, exit code, failure signature and test hash. Validate isolation, timeout,
disabled network and absence of credentials separately with the real container runner.

rejection of an always-zero patch, unchanged tests and a diagnostic report for insufficient evidence.

(15 original and 5 new tests). Verifier tests from the separate PR #3 are not included in that count.
