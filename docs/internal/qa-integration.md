## Run the checks

Use the Python environment described in `demo-handoff.md`, then run from the repository root:

```bash
python -m pytest -q --junitxml=.qa-results/results.xml
```

The exit code determines whether checks passed. The terminal prints a summary and the generated
JUnit XML contains per-test results for the actual run. `.qa-results/` is ignored by Git.
No API key is required. These checks execute trusted fixture code with LocalRunner on the host,
not arbitrary model output. They do not validate container isolation.

Validated on 20 October 2026 with Windows / Python 3.11.9: **56 passed in 30.31 seconds**.
The JUnit report was generated by that run; it is a local execution artifact and is not committed.

## Coverage

`tests/test_demo_scenarios.py` now uses the team `Verifier`, rather than `ReferenceVerifier`.
It checks real broken/good execution, fixed acceptance answers, a prepared good patch, rejection
of an always-zero patch, insufficient evidence and reporting without a patch.

`tests/test_qa_failures.py` exercises:

- Missing imports, syntax errors, setup failures, unrelated passing tests and all-skipped tests
  must not confirm reproduction.
- A real runner timeout must not confirm reproduction.
- A patch changing tests is rejected by the verifier's hash check even if every test passes.
  This check deliberately bypasses the pipeline guard to test the independent integrity rule.
- A patch introducing a syntax error, or one that cannot apply, is rejected.
- The pipeline requests no patch after an import failure or timeout.
- The pipeline completes a generated-demo run using the team verifier and preserves the result
  in history when given a prepared good patch.

Model responses and patches are fixed fixtures. A passing result demonstrates the mechanism,
not NVIDIA/Nebius availability, model quality or a production fix.
